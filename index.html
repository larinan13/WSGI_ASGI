WSGI ⇄ ASGI

⚡ Мост между сервером и Python PEP 3333 → ASGI #async
📜

WSGI · PEP 3333 синхронный

Web Server Gateway Interface — универсальный контракт между сервером и Python.

  • Интерфейс: application(environ, start_response)
  • Решил проблему: фреймворки были привязаны к серверам
  • Синхронный: один запрос → один поток
  • Фреймворки: Flask, Django, Pyramid
⚡

ASGI · Async асинхронный

Asynchronous Server Gateway Interface — эволюция для современных приложений.

  • Интерфейс: async def app(scope, receive, send)
  • Зачем: WSGI не подошла для WebSocket и асинхронности
  • Асинхронный: event-loop, тысячи соединений
  • Фреймворки: FastAPI, Starlette, Django+Channels

⚠️ Почему WSGI уступила ASGI?

Блокировка

Поток ждёт завершения I/O

Нет WebSocket

Только HTTP запрос-ответ

Масштабирование

Много потоков → дорого

🧩 Серверы приложений

🐍 Gunicorn (WSGI)
⚡ Uvicorn (ASGI)
🐝 Daphne (ASGI)
🌽 Hypercorn (ASGI)

Их роль: принимать запросы от Nginx, преобразовывать в вызовы Python-функций (WSGI/ASGI) и возвращать ответ.

📋 7 шагов HTTP-запроса

Шаг 1

🌐 Браузер

Формирует HTTP-запрос и отправляет на сервер

Шаг 2

🔄 Nginx

Принимает, отдаёт статику, проксирует динамику

Шаг 3

🐍 Сервер приложений

Gunicorn (WSGI) или Uvicorn (ASGI) вызывает Python

Шаг 4

🧩 Фреймворк

Flask/Django/FastAPI обрабатывает запрос

Шаг 5

⬆️ Формирование ответа

Фреймворк возвращает ответ, сервер упаковывает в HTTP

Шаг 6

🔙 Обратный путь

Ответ проходит через Nginx обратно

Шаг 7

🌐 Браузер

Получает и отображает ответ

💡
Ключевой вывод: WSGI и ASGI — стандарты интерфейсов, а не серверы. WSGI — надёжная классика для синхронных приложений (Flask, Django).
ASGI — будущее для высоконагруженных API, WebSocket и асинхронности (FastAPI, Django+Channels).
